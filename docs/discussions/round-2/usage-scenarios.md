## 2. 五个候选使用画面

### 场景一：做完作业后，我接下来应该补什么？

学生完成普通作业，发现有错题或拿不准的步骤，但不知道该继续刷题、重新理解概念，还是进入新内容。

可以提供与当前任务有关的题目、作答过程和已有反馈。系统先确认题目及步骤识别是否正确，根据证据提出疑似卡点，通过必要的短问题进一步确认，再建议一项具体学习任务。

学生完成后，通过一道新题或解释任务观察是否能独立完成，再调整为继续巩固、换一种帮助方式或跟上新课。提示后做对与独立完成分别记录。

**核心体验：作业完成后，能得到有依据、可执行的下一步建议。**

### 场景二：开始新章节前，我需要先补基础，还是可以直接学？

学生即将进入新章节，可能具备部分前置知识，也可能存在暂时看不出来的缺口。

可以结合教材章节、当前教学进度和几项短任务，了解已有准备情况。不同学生可能直接进入新内容，也可能先补一个前置概念，再回到当前章节。

补习后的表现影响后续顺序，同时考虑班级进度，避免因不断补基础而脱离当前课堂任务。短任务不足以作出判断时，保留未知状态。

**核心体验：调整学习顺序，在个人准备情况和学校教学进度之间找到衔接方式。**

### 场景三：每天打开时，今天只有二十分钟，先学什么？

学生当天可用时间有限，还要完成学校布置的任务，希望知道先做什么、哪些可以稍后处理。

可以提供可用时间、必须完成的任务，并结合近期学习记录生成少量建议。每项建议说明理由和预计任务范围，允许学生或相应指导者调整选择。

任务未完成时，可以反馈“太难”“时间不够”或“已经会了”；这些反馈与实际作答一起影响下一次安排。时间估计、跨学科安排和任务优先级怎样判断仍需讨论。

**核心体验：在现实时间和任务约束下，帮助选择下一项学习活动。**

### 场景四：连续练习后，我一直在练，为什么还是不会？

学生多次练习仍反复卡住，需要讨论的问题可能包括概念理解、方法使用、表达或对任务的理解，不能仅凭重复答错作出定论。

可以结合几次作答、已有提示和学生解释，提出需要进一步检验的假设，并尝试换一种学习活动，例如看反例、画图、解释步骤或讲给别人听。

随后通过新的任务观察表现，判断是否继续当前方式、调整解释或寻求人工帮助。能够复述答案、使用提示完成与独立解释迁移分别看待。

**核心体验：根据新证据调整学习方法和支持方式。**

### 场景五：阅读或表达后，我读完了，但讲不清楚

学生完成阅读，能够复述部分内容，却难以概括、提出观点或说明依据。

可以围绕有使用授权的文本、学生自己的概括或观点，引导学生找原文证据、解释联系。下一项任务可能是重新读某段、比较两个观点，或修改自己的解释。

系统结合新表达中的证据使用与解释情况，更新下一步任务；讨论重点是帮助学生形成自己的理解和表达。不同年级、文本与任务的反馈标准仍需设计。

**核心体验：将学习方向调整扩展到理解、表达和探究。**

## 3. 这些画面分别在调整什么

| 场景 | 主要调整内容 | 可能依据的证据 |
| --- | --- | --- |
| 作业完成后 | 下一项任务与帮助程度 | 作答步骤、必要追问、新任务表现 |
| 新章节开始前 | 前置知识与新内容的学习顺序 | 教材及课堂进度、短任务表现 |
| 每天打开时 | 时间约束下的任务优先级 | 可用时间、学校任务、近期记录及执行反馈 |
| 连续练习仍困难时 | 学习方法与支持方式 | 多次作答、解释、已用提示和新情境表现 |
| 阅读或表达后 | 理解、证据查找与表达任务 | 原文、学生概括、观点与修改后的解释 |

五个场景可以分别讨论，其共用能力及相互关系尚未确定。数学中的分配律等例子只用于说明交互，不代表已选定首个学科或章节。

## 4. 首页的文字示例

以下为虚构学习情境中的候选画面，尚未实现：

> **今天建议先做什么？**
>
> 先用一道短题确认“分配律”是否掌握。
>
> **为什么？**
>
> 最近两次作答出现了相似错误，还需要进一步确认。
>
> **之后呢？**
>
> 根据这次表现，选择补一个概念，或继续当前章节。
>
> **你可以调整：**
>
> 今天先完成学校作业／换个解释方式。

首页也可能从“做完这次作业后，接下来怎么补”进入。用户尚未选择每日计划入口或作业后入口；两种画面均保留为待讨论项。证据不足时怎样呈现、建议能否解释清楚，也是后续构思重点。

## 5. 谁操作，以及在哪里使用

学生受益与直接操作入口分别讨论。以下组织方式均为候选：

| 组织方式 | 可以怎样参与 | 需要继续想清楚 |
| --- | --- | --- |
| 学生在相应指导下操作 | 提供作答、完成任务、反馈困难并调整建议 | 目标学段、指导方式、设备与使用时段 |
| 家长协助 | 协助材料整理、安排时间和使用指导 | 家长负担、是否影响学生独立完成 |
| 教师组织 | 结合课堂进度组织任务，复核需要介入的判断 | 采集和审核成本、如何支持多个学生 |
| 校内共享设备或纸质任务 | 通过共享终端完成交互，或由组织者发放纸质任务并记录反馈 | 设备安排、分发回收、反馈录入和再次调整成本 |

微信小程序继续作为形态偏好；校内无法使用个人手机时，共享设备、教师工具或纸质任务也可以讨论。当前没有确认哪一种入口可以在目标学校持续使用。

学段使用边界、教师监督指导、内容准确性、个人信息和考试材料等敏感数据、教材及文本授权，需依据[指南原文](../../references/中小学生成式人工智能使用指南（2025年版）.md)进一步细化。组织方式或界面形态本身不能证明已经满足全部使用要求。

## 6. 继续构思的问题

1. 第一个使用画面更接近“每天打开看今天学什么”，还是“做完作业后知道怎么补”？
2. 最想调整的是下一项任务、章节顺序、学习方法，还是跨学科时间分配？
3. 五个场景中，学生愿意提供哪些材料，哪些交互容易打断学习？
4. 建议与学校任务冲突时，学生、家长和老师分别怎样参与调整？
5. 怎样显示建议依据与不确定性，让学生能够理解、纠正并作出选择？
