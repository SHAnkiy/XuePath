## 2. “学习方向”可能包含哪些层次

用户尚未确定调整的粒度。以下是供比较的不同层次，不能直接合并为首版范围。

| 层次 | 一个具体问题 | 可能需要的证据 |
| --- | --- | --- |
| 下一项任务 | 接下来练哪种题、需要哪种解释？ | 当前作答、已有步骤、必要的短诊断 |
| 学科内路径 | 这一章先补哪个前置知识，再学什么？ | 多次作答、知识依赖关系、教材与教学进度 |
| 每日或每周安排 | 有限时间里，哪些任务优先做？ | 学习证据、可用时间、学校任务、阶段目标 |
| 跨学科分配 | 多门学科之间怎样分配精力？ | 各科表现、任务负担、考试安排、学生目标 |

需要继续讨论：跟上课堂、回补基础、应对阶段任务和发展兴趣之间如何取舍？建议由系统直接安排，还是由学生、家长或老师参与选择？

## 3. “普适性”的候选解释

现阶段不能把“学习机缺少普适性”视为已证实的竞争结论。可以分别检验：

- **使用可及性**：是否需要额外硬件？已有设备能否在允许的学习场景中使用？费用是否可接受？
- **教学适配**：是否适配目标教材版本、章节、学校进度和老师的实际作业？
- **个人差异**：能否根据概念理解、方法使用、熟练程度和独立完成情况调整建议？
- **现实约束**：能否适应不同的学习时间、设备条件、支持条件和阶段目标？
- **持续执行**：学生是否愿意长期使用，是否理解并能调整建议？

“支持范围很广”和“对不同学生都有效”需要分别验证。

## 4. 讨论过的候选思路

以下均为助手提出、尚未得到用户确认的方案。它们用于发散思考，不代表已选择的定位、产品范围或路线图。

| 候选方向 | 主要帮助 | 值得讨论的冲突 |
| --- | --- | --- |
| 错因辅导 | 根据已有步骤和必要追问，定位疑似错误原因并辅助订正 | 学生可能只想快速得到答案，诊断却需要参与 |
| 解题思路陪练 | 从学生卡住的位置继续给适量帮助 | 如何获取足够思路证据，同时减少输入负担 |
| 章节学习导航 | 探索前置知识缺口，建议学习先后顺序 | 补基础的建议可能与学校的新课进度冲突 |
| 学习时间规划 | 综合任务、目标与时间安排优先级 | 单靠作答记录，可能不足以了解现实负担 |
| 预习引导 | 帮助学生带着具体问题进入新课 | 提前探索与过度提前讲解之间如何取舍 |
| 反向教学与学生出题 | 让学生讲解、改条件或编题，检验理解 | 学生是否愿意投入，体验是否有吸引力 |
| 师生问题连接 | 帮学生把模糊的“不会”整理为具体卡点 | 增加提问后，怎样控制教师回应负担 |

此前还讨论过教师讲评备课助手、教研组资源复用等教师端切口。它们属于探索历史，未被确认作为首发方向。当前学生端构想不应被这些建议替代。

初中数学、单个年级、一元一次方程、先做网页端等建议，也未被确认。学校付费、家长付费及个人订阅均未形成决定。

## 5. 诊断与调整需要什么证据

这是产品能力的探索边界，不是已经实现的技术方案。

- 教材可以提供范围、术语和学习顺序的参考；导入教材本身不等于完成个人诊断。
- 错题可以提供线索；仅凭一道题答错，不应直接断定稳定的知识漏洞。
- 分析个人解题思路，需要该学生的作答过程、解释或相关验证结果。
- 图片识别错误、抄写问题、计算失误和概念误解，需要考虑不同的处理方式。
- 可以探索区分“证据不足”“疑似薄弱点”和“经进一步任务支持的判断”；展示方式仍待设计。
- 使用提示后做对，与独立完成新题，应分别记录。
- 调整建议需要随新证据更新，并允许学生或教师纠正系统判断。

一个仅用于讨论的例子：学生把 `2(x-3)` 展开为 `2x-3`，可以产生“分配律使用不完整”的假设，再通过短问题检验。这个例子不能证明系统已经具备可靠的错因分析能力。

## 6. 使用者、参与者和付费方

| 角色 | 可能关心的价值 | 当前尚不清楚的部分 |
| --- | --- | --- |
| 学生 | 知道下一步学什么，获得可理解、可执行的帮助 | 是否愿意提供过程、接受建议并持续执行 |
| 家长 | 了解进展，获得可靠且负担可接受的支持 | 是否认可价值，是否愿意支付 |
| 老师 | 学习支持与课堂目标一致，发现有证据的共性问题 | 如何参与，是否增加额外工作 |
| 学校 | 教学适配、组织实施、效果与成本可评估 | 是否需要采购，预算与决策流程是什么 |

有学校资源意味着可以开展访谈和探索试用，不等于已有学校订单。学生喜欢、家长愿意支付和学校愿意组织使用也需要分别验证。

## 7. 订阅与 credits 的开放问题

用户倾向订阅含 credits，并支持追加购买。以下计费思路仍是候选项：

- 按完整学习任务计量，一次任务包括必要的识别、追问、反馈和验证。
- 面向家庭的会员套餐。
- 面向学校的学期或年度服务名额，以及共享使用额度。
- 基础学习规划包含在订阅中，较高成本的处理任务另计用量。

需要验证：

1. 按对话条数计费，是否会抑制有价值的解释与追问？
2. 一个完整任务如何定义，怎样让学生和付款方理解费用？
3. 识别或系统失败如何处理，额度不足时如何保证体验可预期？
4. 实际处理、重试、内容维护和服务支持的成本是多少？
5. 谁支付，按什么周期支付，追加购买是否符合其使用习惯？

当前没有确定价格、额度、续费规则或超额收费方式。

## 8. 如何形成需求证据

以下是待讨论的研究方法，不是已批准的执行计划，也没有预设结果。

- 观察学生最近一次如何决定“接下来学什么”，了解其现有办法和困难。
- 请老师展示当前教学进度、日常练习安排及已有的学生支持方式。
- 分别了解家长和校方认可的价值，以及同类工具的实际支付或采购过程。
- 对真实任务进行小范围辅助交付，观察学生是否执行、是否需要大量帮助。
- 将一次使用后的表现与后续独立任务表现区分，探索如何评估掌握与保持情况。
- 记录任务耗时和额外负担，检查产品是否只是增加了另一套学习流程。

注册量、上传量、对话量和查看分析报告的次数，可以描述使用情况；是否改善学习决策或学习效果，还需要单独设计验证。
