# 第一轮讨论：考察问卷与初步回应

本轮用于把最初的 AI 教学产品想法讲具体，梳理已有回应，并找出还需要调查或作出选择的问题。目前尚未形成完整商业方案。

## 材料与形成经过

- [考察问卷](questions.md)：提问材料，保留 Q1–Q8 原题和填写区。
- [初步回应与产品探索](response.md)：已有想法、讨论记录和候选方案的整理稿，作为本轮回应材料阅读；不等于问卷已逐题答完。

根据用户于 2026-10-07 补充的经过：项目发起人先提出初步想法，用户借助技能生成考察问卷并交给发起人，随后发起人建立仓库；问卷文件是在建库后才加入仓库。此经过来自用户说明，不能用 Git 入库顺序反推材料的实际形成顺序。

用户认为产品探索稿回应了早期问卷中的一些问题，因此本轮将二者放在一起对照。探索稿具体如何生成仍未核验，其内容也包含明确标注的助手建议，不将整篇归为发起人的已确认回答。

## 题目与已有回应对照

“已有回应”表示文档中有相关内容，不代表已有证据支持或已经形成决定。

| 问卷题目 | 回应稿中的相关内容 | 还需要补充 |
| --- | --- | --- |
| Q1：替谁解决什么问题 | §1 用户方向、§2 学习方向、§4 候选思路 | 选定具体用户、场景与问题，写出一句话定位 |
| Q2：谁用、谁付钱、谁决定、谁否决 | §6 使用者、参与者和付费方 | 购买决策者、否决者、资金来源和角色关系 |
| Q3：是否存在真实需求 | §1 尚未开展校方访谈、§8 需求证据方法 | 真实问题案例、现有处理方式、成本和实际反馈 |
| Q4：为什么值得现在花钱 | §6 可能的角色价值、§8 验证方法 | 购买优先级、可衡量变化及其证据 |

| Q6：怎样开始与学校合作 | §1 可接触学校资源、§6 学校角色 | 首次接触目标、具体下一步、试用到购买的路径 |

回应稿中的诊断证据、功能候选、订阅与 credits 等内容是相关产品探索，保留其未确认状态。

## 后续如何维护

1. 补充回答时，在问卷对应题目的填写区记录具体回应，注明日期，并区分事实、推测和未知。
2. 已有长篇内容可以链接到回应稿对应章节，不必重复抄写；助手建议不得直接作为人类回答或调查证据。
3. 回应发生变化时，同步更新上表及回应稿相关内容；保留未解决问题，避免把猜想写成决定。
4. 形成产品决定时，在回应稿“待形成的决定”中记录日期、选择和依据；后续轮次另建目录并引用本轮材料。
